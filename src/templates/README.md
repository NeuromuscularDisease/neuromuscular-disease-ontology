# ROBOT Templates

This directory contains ROBOT template CSV files used to build and extend the
Neuromuscular Disease Ontology (NMDO).

---

## Template files

### Core ontology template

| File | Description |
| --- | --- |
| `nmdo.tsv` | Main ODK-managed class template, processed by the standard `make` pipeline |

### PROMOT annotation flattening templates

Generated by `../scripts/parse_promot.rb` and `../scripts/llm_match_promot.rb`.
See `../scripts/CHANGES.md` for full audit trail and design decisions.

| File | Description | Process with ROBOT? |
| --- | --- | --- |
| `annotations-robot-template.csv` | Declares 14 new `owl:AnnotationProperty` entries (7 semantic + 7 `_label` siblings). **Process this first.** | Yes — Step 1 |
| `promot-annotations-existing.csv` | Classes matched to NMDO by IRI or SKOS cross-reference. ROBOT-ready. | Yes — Step 2 |
| `promot-annotations-llm-matched.csv` | LLM best-guess matches for PROMOT classes not found in NMDO. **Requires human accept/reject review before processing.** Each class carries an `rdfs:comment` with the LLM match score for clinician review. | After review |
| `promot-annotations-missing.csv` | PROMOT classes with no NMDO equivalent. For curator review — decide whether to add as new NMDO class or discard. | Not directly |
| `promot-annotations-llm-unmatched.csv` | Classes that scored below the LLM threshold (0.20). For curator review. | Not directly |
| `promot-annotations-llm-conflicts.csv` | NMDO IRIs claimed by >1 PROMOT class. Curator flag: consider whether NMDO needs splitting. | Not directly |

## Build process — PROMOT annotation flattening

### Prerequisites

- ROBOT installed at `~/bin/robot` (`java -jar ~/bin/robot.jar`)
- RVM Ruby 3.2.4 at `/home/osboxes/.rvm/rubies/ruby-3.2.4/bin/ruby`
- NMDO semantic search service running at `https://simpathic.services/llm_search/`

### Step 1 — Generate templates (from `src/scripts/`)

```bash
# Full extraction (all PROMOT classes)
ruby parse_promot.rb promot_V0.71.owl ../../nmdo-full.owl

# Scoped extraction (one subtree — recommended for iterative review)
ruby parse_promot.rb promot_V0.71.owl ../../nmdo-full.owl <root-class-IRI>

# Example: "Examination by method" subtree
ruby parse_promot.rb promot_V0.71.owl ../../nmdo-full.owl http://snomed.info/id/315306007
```

Then run the LLM matching pass:

```bash
ruby llm_match_promot.rb          # default threshold 0.20
ruby llm_match_promot.rb 0.30     # stricter threshold
```

This produces three files:

- `promot-annotations-llm-matched.csv` — one deduplicated row per NMDO IRI (annotations merged when multiple PROMOT classes hit the same IRI)
- `promot-annotations-llm-unmatched.csv` — classes below the score threshold
- `promot-annotations-llm-conflicts.csv` — NMDO IRIs claimed by >1 PROMOT class (curator review required)

### Step 2 — Review `promot-annotations-llm-matched.csv`

Open the file and check the `LLM Score` and `LLM Match Note` columns.

- Score >= 0.50: usually reliable
- Score 0.30–0.50: check the match — may be same domain but wrong specific class
- Score < 0.30: likely wrong — delete the row or move to missing

Also review `promot-annotations-llm-conflicts.csv`: each row flags an NMDO class that
multiple PROMOT tools were mapped to. Decide whether NMDO needs to be split into
finer-grained classes before the next batch.

For rejected rows, refer back to `promot-annotations-missing.csv` to find the
corresponding PROMOT class with its full annotation data.

### Step 3 — Apply with ROBOT (from repo root)

```bash
# Declare annotation properties
~/bin/robot template \
  --prefix "nmdo: https://w3id.org/nmdo/" \
  --input nmdo-full.owl --merge-before \
  --template src/templates/annotations-robot-template.csv \
  --output /tmp/step1-props.owl

# Merge into full ontology
~/bin/robot merge \
  --input nmdo-full.owl --input /tmp/step1-props.owl \
  --output /tmp/nmdo-merged.owl

# Apply class annotations
~/bin/robot template \
  --prefix "nmdo: https://w3id.org/nmdo/" \
  --input /tmp/nmdo-merged.owl \
  --template src/templates/promot-annotations-llm-matched.csv \
  --output /tmp/annotations-only.owl

# Final merge — open in Protege to verify before PR
~/bin/robot merge \
  --input /tmp/nmdo-merged.owl --input /tmp/annotations-only.owl \
  --output /tmp/nmdo-preview.owl
```

> The `--prefix "nmdo: https://w3id.org/nmdo/"` flag is **required** on every
> `robot template` call. Without it, ROBOT throws `ANNOTATION PROPERTY ERROR`
> even when the properties are declared in the input ontology.

### Step 4 — Verify in Protege, then PR

Open `/tmp/nmdo-preview.owl` in Protege and confirm:

- Assessment tool classes carry `assesses_phenotype` annotations
- No new spurious parent classes have been created
- `rdfs:comment` on matched classes shows expected LLM score

Then commit and push `promot_integration` branch and open PR targeting `main`.

## Annotation properties introduced

All in namespace `https://w3id.org/nmdo/` (prefix `nmdo:`):

| Property | Semantic role | Source in PROMOT |
| --- | --- | --- |
| `nmdo:associated_phenotype` | HPO phenotypes characterising a class | RO:0004029 + PROMOT:2000006 + RO:0000091 |
| `nmdo:assesses_phenotype` | HPO phenotype a clinical tool detects/measures | PROMOT:2000002 → HP fillers |
| `nmdo:assesses_function` | WHO-ICF body function/structure a tool measures | PROMOT:2000002 → ICF fillers |
| `nmdo:captures_data_about` | CRF data-model concept captured by tool | PROMOT:2000002 → PROMOT-internal fillers |
| `nmdo:associated_function` | WHO-ICF functional capacities (b-codes) | RO:0002328 |
| `nmdo:involved_in` | WHO-ICF activities/participation (d-codes) | RO:0002331 |
| `nmdo:located_in` | WHO-ICF body structures (s-codes) | RO:0001025 |

Each property has a parallel `_label` sibling (e.g. `nmdo:assesses_phenotype_label`)
storing human-readable labels in the same pipe-separated order as the URI column.
